# 展示PC 運用ガイド（スタッフ向け）

展示PC（Windows）で Project Chrome を **起動 → 体験 → 困った時の復旧 → 終了** するための手順です。
開発担当でなくても、この文書だけで操作できることを目標にしています（#21）。

> 書いてある操作は、最新 develop に実装済みのものだけです。
> 「要実機確認」の項目は、展示PCでまだ確かめていません。確かめたら [確認の記録](#確認の記録) に書き、印を外してください。

---

## 1. 毎日の開始

1. カメラ（USB）をPCにつなぎ、インターネットと **会場の Wi-Fi**（スマホでレシートを受け取る時に使う）につながっていることを確認します。
2. HAL208 フォルダーの **`start-exhibition.cmd`** をダブルクリックします（デスクトップのショートカットでも可）。
3. 黒い画面に確認結果が出て、Chrome（無ければ Edge）で `http://localhost:8000` が開きます。
   - `[OK]` だけなら成功です。黒い画面は15秒後に自動で閉じます（すぐ閉じても構いません）。
   - `[OK] スマホ受取用のアドレス：http://192.168.…:8001` が出ていれば、QR 受取が使えます。
   - `[注意]`・`[エラー]` が出たら [4. 困った時](#4-困った時症状--確認--復旧) を見てください。
4. 入店アニメーションが流れます（`SKIP SEQUENCE` または `Esc` で飛ばせます）。
5. カメラの許可を求められたら **「許可する」** を選びます（同じPC・同じURLなら次回から聞かれません）。
6. **`F11`** で全画面にします（ブラウザーの機能。戻す時ももう一度 `F11`）。
7. 画面上部が **CAMERA ONLINE**、人が立つと **POSE TRACKING: ACTIVE** になれば準備完了です。

## 2. 毎日の終了

1. ブラウザーのタブ（またはウィンドウ）を閉じます。カメラが解放されます。
2. HAL208 フォルダーの **`stop-exhibition.cmd`** をダブルクリックします。
   - `[OK] サーバー（PID …）を停止しました。` と出れば完了です。
   - 停止するのは `start-exhibition.cmd` で起動したサーバーだけです。他のアプリは止めません。
   - スマホでまだ受け取っていないレシート画像も、この時に消えます（サーバーのメモリーにだけ置いているため）。
3. 必要ならPCをシャットダウンします（シャットダウンだけでもサーバーは止まります。次回の起動に影響しません）。

## 3. 設置と体験の操作

### 設置（カメラ位置・距離・照明）

| 項目 | 内容 |
|---|---|
| 写る範囲 | 体験者の **頭から腰まで、腕を上げた時の手先まで** が映るようにします。腕の追跡と手の形の判定に必要です。 |
| 人数 | 追跡は **1人分** です（体・顔とも1人）。後ろを人が通らない向きに置きます。 |
| 距離 | 立ち位置を床にテープで示します。距離は展示PCで決めて記入：`____ m`（要実機確認）。目・マスク・猫耳は顔が大きく映るほど精度が上がります。 |
| 照明 | 顔と腕に正面から光が当たるようにし、窓や照明を背負う逆光を避けます。腕のクロームは部屋の明るさ・色に合わせて変わります。 |
| 画面 | 体験者から画面が見える位置に置きます。映像は鏡のように左右反転して表示されます。 |

### 音量

- 効果音は **最初のクリック（またはキー操作）の後から** 鳴ります（ブラウザーの制限）。
- 大きさはPC本体の音量と、`スタッフ用設定 / SYSTEM` の **Volume** で調整します。
- 消音は `スタッフ用設定` の **Sound** のチェックを外すか、**`M` キー** です（もう一度押すと戻ります）。

### 来場者の体験の流れ

| 画面 | 来場者の操作 | 結果 |
|---|---|---|
| 装備選択 | 右のストアで **ARMS / EYES / MASK / HEAD** を選ぶ（タブ、または ‹ › ボタン）。カードでパーツを選ぶ | EYES・MASK・HEAD の変更（目の色、マスク、猫耳など）はすぐ映像に反映 |
| 装備選択 | **「装着して体験する」**（APPLY）を押す | 「装着中…」の後、約1秒で体験画面へ |
| 体験 | 腕を動かす・手の形を作る | 画面左下の ARM CONTROL のとおりにギミックが出る（下の表） |
| 体験 | **「? GUIDE」** | 操作の説明を表示／非表示 |
| 体験 | **「写真を撮る」** | 装備をつけた映像を PNG で **展示PC** に保存（ブラウザーのダウンロード先。通常は「ダウンロード」フォルダー） |
| 体験 | **「🛒 この装備を購入（体験）」** | 写真入りのレシートをスマホで受け取る流れへ（[下の表](#仮想購入と-qr-受取)） |
| 体験 | **「← BACK TO SELECT」** | 装備選択に戻る（選んだ装備は残る） |
| 装備選択 | **「↺ RESET」** | 装備・目・マスク・耳・タブを初期状態に戻す（体験画面では表示されません） |

腕のギミック（GADGET が AUTO の時。初期設定）

| 手の形・動き | 効果 |
|---|---|
| 人差し指だけを上へ立てる | FLAME（指先に火） |
| 腕を上げて手を開く → 握る | PLASMA |
| 人差し指と小指を立てる | NET |
| 人差し指を横に向け親指を立てる | HOOK |
| 拳で腕を勢いよく伸ばす | FIST |

### 仮想購入と QR 受取

お金は動かない展示用の体験です。スマホは **展示PCと同じ Wi-Fi** に接続している必要があります。

| 画面 | 操作 | 補足 |
|---|---|---|
| 案内 | **「撮影へ進む」** / 「やめる」 | 30秒操作が無いと自動で閉じます |
| 3・2・1 | ポーズを決める | 0 で撮影。追跡と描画は続いています |
| 写真の確認 | **「この写真で購入」** / 「撮り直す」 / 「やめる」 | 45秒操作が無いと自動で閉じます |
| QR | スマホのカメラで読み取る →「終了」 | QR の画面は120秒で自動で閉じます |
| スマホ | 受取ページの **「画像を保存」**、できなければ画像を長押しして保存 | 受取できるのは **登録から10分** です。サーバーを止めても消えます |

- 「やめる」・BACK TO SELECT・RESET・スタッフ用リセットは、展示PC側の購入画面だけを片付けます。
  すでに QR を表示した前の人のレシートは、10分の期限まで受け取れます。
- QR に入るのは `http://<展示PCの LAN アドレス>:8001/r/<番号>` です。`localhost` の URL はスマホでは開けません。
- 受取ページは番号を知っている人なら期限内に誰でも開けます（ログインはありません）。QR をむやみに撮影させないでください。
- iPhone（Safari）・Android（Chrome）での保存手順は要実機確認です。

> 「写真を撮る」で保存した PNG には来場者の顔が写り、展示PCに残ります。展示中・展示後の扱い（削除の時期など）はチームで決めて記入：`________`。
> GitHub や共有フォルダーにはアップロードしません。

### スタッフの操作

| 操作 | 使う時 |
|---|---|
| **`Ctrl` + `Shift` + `R`** → **`Enter`** で実行 / **`Esc`** で取り消し | 体験画面のまま次の人へ交代する時のリセット。RESET と同じく初期状態に戻り、購入の途中なら取り消します |
| `スタッフ用設定 / SYSTEM`（右パネル下部。装備選択画面だけ） | Sound・Volume、Effects quality（FPS が低い時は LOW）、Room reflections、計測情報・骨格の表示 |
| ↺（画面下の体験ステップ横） | 入店アニメーションをもう一度流す |
| `F5` | ページの再読込。体験の状態は初期化されますが、カメラの許可は残ります |

キーボード操作の注意

- `Ctrl` + `Shift` + `R` はブラウザーでは「キャッシュを無視して再読込」です。作品のページを操作中は作品側が先に受け取ってリセット確認を出しますが、
  アドレスバーに文字入力中などはブラウザーの再読込になります（要実機確認：Chrome / Edge それぞれで、確認欄が出て再読込されないこと）。
- **`G` キー** はギミックのテスト発射です（来場者向けではありません）。
- `M`・`G` は、プルダウン（Ear model、Effects quality）を選択中に押しても反応します。キーボードは来場者の手の届かない所に置きます。

## 4. 困った時（症状 → 確認 → 復旧）

画面の案内は、右パネル下部の案内欄に出ます（体験画面ではパネルが隠れるので、`← BACK TO SELECT` で戻ると見えます）。

### 起動ツール（黒い画面）

| 症状 | 確認 | 復旧 |
|---|---|---|
| `Node.js（推奨）または Python 3 が見つかりません` | Node.js がインストールされているか | 開発担当に依頼して [初回だけの準備](#5-初回だけの準備開発担当) を行う |
| `[注意] Python で起動するため、仮想購入の QR 受取は使えません` | Node.js が無い・古い（黒い画面の [注意] に理由が出ます） | 体験と「写真を撮る」は使えます。QR 受取が必要なら Node.js を入れる（開発担当） |
| `作品フォルダー（project-chrome\index.html）が見つかりません` | `start-exhibition.cmd` を HAL208 フォルダーの外へ移動・コピーしていないか | HAL208 フォルダーの中のものを使う。デスクトップには **ショートカット** を置く |
| `ポート 8000（または 8001）は他のアプリが使用中` | 表示されたアプリ名・PID | 手動で起動したサーバー（`npm run serve` など）なら、その黒い画面で `Ctrl` + `C`。他のアプリならそれを閉じてやり直す。ツールは他のアプリを止めません |
| `インターネット上の読込先に接続できません`（[注意]） | Wi-Fi・LAN ケーブル、プロキシの有無 | 接続を直してから `F5`。プロキシ環境では [注意] が出ても作品は動く場合があります |
| `LAN の IPv4 アドレスがありません`（[注意]） | Wi-Fi に接続しているか | 接続してから終了 → 開始。QR 以外は使えます |
| `サーバーが起動しませんでした` | 黒い画面に出たログ（`.exhibition\server.log`） | 内容を写真に撮って開発担当に相談 |
| `JavaScript の配信形式が「text/plain」…`（[注意]。Python で起動した時だけ） | Windows の拡張子 `.js` の関連付け設定 | 画面が「起動中...」のまま進まない原因です。Node.js で起動すれば起きません。PCの設定変更になるので開発担当に相談 |
| `既にこのツールで起動しています` | — | 正常です。ブラウザーで作品が開きます |
| 初回に「Windows セキュリティの重要な警告」（Node.js の通信の許可）が出た | — | スマホ受取（ポート 8001）に必要です。どのネットワークで許可するかはPCの設定変更なので、開発担当・PCの管理者の判断に従う（要実機確認） |

### 作品の画面

| 症状 | 確認 | 復旧 |
|---|---|---|
| 「モデルを読み込めませんでした: …」 | インターネット接続 | 接続を直して `F5` |
| 「カメラにアクセスできませんでした: Permission denied」など（許可拒否） | アドレスバー左のアイコン →「カメラ」が「ブロック」になっていないか | 「許可」に変えて `F5`。Windows のプライバシー設定でカメラが止められている場合は開発担当に相談 |
| 「カメラにアクセスできませんでした: Could not start video source」など（使用中） | Teams・Zoom・カメラアプリ等がカメラを使っていないか | そのアプリを閉じて `F5` |
| 「カメラにアクセスできませんでした: Requested device not found」など（カメラなし） | USB の接続 | つなぎ直して `F5` |
| 体験中に映像が止まる・真っ黒になる（USB が抜けた等） | USB の接続 | つなぎ直して `F5`。今の develop は抜けたことを自動では検知しません（要実機確認） |
| 画面が「起動中...」のまま | 黒い画面の [注意]、インターネット | 上の表の該当行を参照。`F5` で直らなければ終了 → 開始をやり直す |
| POSE TRACKING が LOST のまま | 立ち位置、逆光、2人以上映っていないか | 立ち位置の印に立ってもらい、照明を調整 |
| 動きがカクカクする（FPS が低い） | `スタッフ用設定` の 計測情報を表示 で FPS を確認 | Effects quality を LOW、Room reflections を OFF。他のアプリを閉じる |
| 「写真を撮る」が「カメラの準備ができていません」 | カメラ映像が出ているか | 映像が出てから撮る |
| 写真が保存されない | ブラウザーが「複数ファイルのダウンロード」の許可を求めていないか（要実機確認） | 「許可」を選ぶ。保存先はブラウザーのダウンロード設定で確認 |
| 音が鳴らない | Sound のチェック、Volume、PC の音量、`M` で消音していないか | 画面を一度クリックしてから試す |
| 操作がおかしい・固まった | — | まず `Ctrl` + `Shift` + `R` → `Enter`。直らなければ `F5`。それでも直らなければ終了 → 開始 |

### 仮想購入・スマホ受取

| 症状 | 確認 | 復旧 |
|---|---|---|
| 「レシートのサーバーに接続できません」「レシートのサーバーが起動していません」 | 作品をどの方法で起動したか（すぐ下の3行のどれに当たるか） | 起動方法ごとに下の手順で直す |
| 　└ 手動で `python -m http.server`（または `npm run serve`）を起動していた | `start-exhibition.cmd` とは別に、サーバーを動かしている黒い画面（ターミナル）が開いていないか | ① その黒い画面で `Ctrl` + `C` を押して止める（`stop-exhibition.cmd` は手動で起動したサーバーを止めないため、先に止めないと次の起動がポート競合で止まります）→ ② `start-exhibition.cmd` |
| 　└ `start-exhibition.cmd` で起動したが、Python で起動していた | 起動時の黒い画面に「[注意] Python で起動するため、仮想購入の QR 受取は使えません」が出ていたか。その直前の [注意] が「Node.js が見つかりません」か「Node.js … は古いため使えません」か | ① 開発担当に **Node.js 20.19 以上** の導入（または更新）を依頼する → ② 導入後に `stop-exhibition.cmd` → `start-exhibition.cmd` → ③ 黒い画面に `[OK] Node.js 20.19 以上の版` が出たことを確認。導入するまでは再起動しても Python が選ばれ、QR 受取は使えません（体験と「写真を撮る」は使えます） |
| 　└ `start-exhibition.cmd` で Node.js で起動していた（`[OK] Node.js …` が出ていた） | サーバーを止めていないか（`stop-exhibition.cmd` の実行、PC のスリープ・再起動） | `start-exhibition.cmd` で起動し直す |
| 「LAN に接続されていないため、QR を発行できません。」 | 展示PCが Wi-Fi・LAN につながっているか | つないでから、もう一度「🛒 この装備を購入（体験）」 |
| スマホで QR を読んでもページが開かない | スマホが展示PCと **同じ Wi-Fi** か（モバイル回線では開けません）。ゲスト用 Wi-Fi は端末どうしの通信が禁止されていることがあります | 同じ Wi-Fi に接続して読み直す。会場の Wi-Fi で通じない場合は開発担当に相談（PCのファイアウォール設定・会場ネットワークの条件。要実機確認） |
| 「受取期限が過ぎたか、番号が正しくありません。」 | 登録から10分を過ぎたか、サーバーを止めた・再起動したか | もう一度購入の流れで撮り直す |
| 「撮影に失敗しました」「カメラの準備ができていません」 | カメラ映像が出ているか | 「閉じる」→ 映像が出てから再度購入 |
| Wi-Fi を付け替えた後に QR が開けない | — | 新しく作る QR には今のアドレスが入ります。もう一度購入の流れを行う |

カメラのエラー文はブラウザー（Chrome / Edge）の版で変わることがあります。上の英語は例です。
カメラ切断から再読込なしで復帰する機能は #20 で追加予定です。統合されたらこの表を更新します。

## 5. 初回だけの準備（開発担当）

毎日の開始・終了では `npm install` や `git pull` を実行しません（展示用サーバーは追加の npm パッケージを使いません）。
更新が必要な時は開発担当が展示前に行い、[確認の記録](#確認の記録) に commit を書きます。

1. **Node.js 20.19 以上**（LTS）をインストールします（[nodejs.org](https://nodejs.org/)）。QR 受取に必要です。
   Node.js が無い PC では Python 3.8 以上で代わりに起動できますが、QR 受取は使えません。
2. **Chrome または Edge** を用意します。
3. 作品を取得します（展示に使う branch / commit はチームで決めたものにします）。

   ```bash
   git clone https://github.com/PI11A203-lab/HAL208.git
   cd HAL208
   git switch develop
   ```

4. `start-exhibition.cmd` を一度実行し、カメラを許可して設置を確認します。
   初回は Node.js の通信の許可（Windows セキュリティの警告）が出ることがあります。会場のネットワークに合わせてPCの管理者と決めます。
5. 会場の Wi-Fi で、スマホから受け取れるか確認します。個人の写真を使わずに試す時は `http://localhost:8000/dev/qr-test.html` を開き、表示された QR をスマホで読みます。
6. `start-exhibition.cmd` / `stop-exhibition.cmd` を右クリック →「ショートカットの作成」→ デスクトップへ移動します。

補足

- フォルダーのパスに空白・日本語が入っていても動きます。
- 別のポートで起動する時は、コマンドプロンプトで `start-exhibition.cmd -Port 8080 -LanPort 8081` のように指定します（展示画面のポートを変えるとカメラの許可を取り直します）。
- Node.js があっても Python で起動したい時は `start-exhibition.cmd -Python` です（QR 受取は使えません）。
- `.exhibition\` に実行中のサーバーの記録とログができます（Git の管理対象外）。消しても構いませんが、起動中に消すと `stop-exhibition.cmd` で止められなくなります（その場合はPCを再起動）。
- 中身は `scripts\start-exhibition.ps1` / `scripts\stop-exhibition.ps1` です。展示用サーバーそのものは `npm run serve`（`scripts\serve.mjs`）と同じです。
  PCの実行ポリシー設定は変更せず、その実行の間だけ許可して動かします。

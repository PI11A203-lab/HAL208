# 手のジェスチャーによる充電・シールド（#9）

develop の腕のギミック（#14・#18）の仕組みに統合している。手の認識・拳/開いた手の判定・PLASMAの溜めは既存実装を使い、重複する推論や状態機械は持たない。

## 動作
| 操作 | 結果 |
|---|---|
| 腕を構えて手を開く（PLASMA/AUTO） | 既存の溜め。**溜めに合わせて腕の発光が強まり**、解除で基準の外観へ戻る |
| 腕を構えず、開いた手を約0.25秒保持 | シールド（手首の先に六角形）。最長3秒、手を解くまで再発動しない、解除後0.6秒待機 |
| CHARGE ボタン | 構えたものとして溜め、満タンか約1.2秒で発射（GADGETがOFFの時は案内） |
| SHIELD ボタン | 同じシールド制御を通して発動（クールダウン・最長時間は手と同じ）。腕が映っていない時は画面中央に出る |

## 構成
- `gadget-logic.js`：`createShieldController`（純粋ロジック。`tests/gadget.test.mjs`）
- `effects.js`：シールドmesh（初期化時に作成して再利用）と、簡易腕の発光
- `arms.js`：GLB腕の `setBoost()`（発光の一時強調。`applyAppearance` で戻す）
- `main.js`：`updateShield` / `updateArmGlow` / `stopGesture`（BACK・RESET・phase変更で解除）

## 契約
- 手の喪失（腕の追跡切れ・指の追跡なし）、phase変更、BACK、RESETでシールドと発光を即解除。
- シールドの手の判定は、指に分かれたGLB腕で手を追跡している時のみ（既存の `currentLabel`）。
- SHIELDボタンは腕が映っていなくても使える（画面中央）。CHARGEボタンは発光させる腕が必要なため、腕が映っている時のみ。
- 充電の発光は、develop側の溜め（`charge`）と連動する。拳＝充電ではなく、既存の「開く＝溜め、握る＝発射」に従う。

## 既知の制約（実機未確認）
- 展示PCでの誤判定・遅延・FPSは未計測。
- 複数人の確実な排除は保証しない（既存の `assignHands` による腕との対応のみ）。
- シールドの手の判定は、既存の安定化（直近6フレーム中4回）を通るため、反応にわずかな遅れがある。

# 手のジェスチャー（#9）

拳を握る＝充電（腕の発光）、手のひらを開く＝シールド。アクション体験中だけ有効。

## 構成
- `project-chrome/js/gestures.js`：21点→姿勢分類、保持/クールダウンの状態機械（純粋ロジック。`tests/gestures.test.mjs`）
- `project-chrome/js/hand-input.js`：HandLandmarker初期化・推論（約15Hzへ間引き）・結果整形。CDNクラスはmain.jsから注入
- `project-chrome/js/effects.js`：腕の発光とshield mesh（初期化時に作成して再利用）
- `project-chrome/js/main.js`：loop接続、HUD、CHARGE/SHIELDボタン

## 契約
- 閾値は `HAND_CONFIG` 一箇所（ms単位）。保持250ms、中間姿勢の許容120ms、1回の最長3000ms、解除後600ms待機。
- 最長時間を使い切ると、姿勢を一度変えるか手を離すまで再発動しない。
- 認識喪失（欠落・信頼度不足・非有限点・画面外）、手の切替、phase変更、BACK、RESETで候補・保持時間・効果を即解除。
- ボタンは同じ `createGestureTracker().force()` を通り、クールダウン・phase・RESETの条件が同じ。腕が映っていなくても押せる（シールドは画面中央、充電は腕が映った時に見える）。手の認識は腕の追跡中のみ。手の喪失では止まらず、最長時間で終了。
- 手の選択：Pose手首との距離が肩幅の0.9倍以内の手のみ。Poseが取れない時だけ信頼度最大の手を使う。
- handednessは手の同一性判定にのみ使用（映像は未反転入力のため左右ラベルは実際と逆になり得る）。
- 手モデルの読込・推論に失敗しても例外にせず、案内を出してボタンで継続。Pose/カメラは止めない。

## 既知の制約（実装時点・実機未確認）
- 親指は判定に使わない（不安定なため）。
- 手の推論は新たにCPU/GPU負荷を追加する。展示PCのFPS・遅延は未計測。
- 複数人の確実な排除は保証しない（Pose手首との近さによる軽減のみ）。
- 発光は腕のネオン/金属材質を共有する左右両腕に適用。猫耳の材質は別インスタンスで影響しない。

# 腕モデル（GLB）の規格

Issue #7 で追加した展示用の腕モデルの置き場所と、モデルとプログラムの間の決まりです。
新しい腕モデルを作るときも、この規格に合わせると `js/arms.js` の読込処理をそのまま使えます。

## ファイル一覧

| ファイル | 内容 | 容量 | 使う装備 |
|---|---|---|---|
| `arm-mk1.glb` | 筋肉の形に沿ったクローム装甲と露出した油圧機構を持つ5本指の義手（基準モデル、右腕） | 約1.5 MB（1,538,204 bytes）、約64,000三角形 | MK-I（`config.js` の `DESIGNS.mk1.model`） |
| `arm-neon.glb` | 細身で角のある黒いクロームの装甲、板の縁に沿った発光ライン、鋭い指先（右腕） | 約0.6 MB（609,716 bytes）、約20,000三角形 | NEON EDGE（`DESIGNS.neon.model`） |
| `arm-titan.glb` | 厚い装甲ブロック、外側の支持フレーム、大型ピストン、歯車状の肘、太い指の作業用ハンド（右腕） | 約1.1 MB（1,126,092 bytes）、約44,600三角形 | TITAN FRAME（`DESIGNS.titan.model`） |

## ノード（部品）

腕は1つの骨格（rig/skinning）ではなく、関節ごとに独立した3つの部品で構成します。

| ノード名 | 原点（回転中心） | +Y 方向 | 合わせる区間 |
|---|---|---|---|
| `UpperArm` | 肩関節 | 肘へ向かう | 肩 → 肘 |
| `Forearm` | 肘関節 | 手首へ向かう | 肘 → 手首 |
| `Hand` | 手首関節 | 指先へ向かう | 手首 → 手の先端 |

- ノード名は大文字・小文字を含めて上の表と一致させます。1つでも欠けると読込失敗として扱い、簡易形状で表示します。
- 各部品の **前面（カメラに向けたい面）は +Z** に作ります。プログラムは +Z をできるだけカメラ側へ向けます。
- 手首のひねり（ロール）は追跡していないため、手は前腕の延長線上に置きます。手の長さは `handRatio`（前腕の長さに対する比率。`arm-mk1` は 0.7）で決めます。
- 手は「手の甲＝前面（+Z）」として作ります。
- ファイル内での部品の並べ方（位置・回転・拡縮）は使いません。各ノードの原点からの形状だけを使います。`arm-mk1.glb` では見やすいように横へ並べています。

## 指の節（指の追跡）

`Hand` の子に、指の節を15個の独立したノードとして入れます。手を追跡している間は、MediaPipe Hand Landmarker の21点に合わせて1節ずつ動き、追跡していない間はモデル上の形（少し曲げた手）のまま手のひらについていきます。

| ノード名 | 合わせる区間（ランドマーク番号） |
|---|---|
| `Thumb1` `Thumb2` `Thumb3` | 1→2、2→3、3→4 |
| `Index1` `Index2` `Index3` | 5→6、6→7、7→8 |
| `Middle1` `Middle2` `Middle3` | 9→10、10→11、11→12 |
| `Ring1` `Ring2` `Ring3` | 13→14、14→15、15→16 |
| `Pinky1` `Pinky2` `Pinky3` | 17→18、18→19、19→20 |

- 各節の原点＝付け根の関節、+Y＝次の関節、+Z＝爪（手の甲）側。`Hand` に対する位置・回転が「追跡していない時の形」になります。
- 各節に glTF の extras（Blender のカスタムプロパティ）で `baseLength`（節の長さ）と `baseRadius`（節の太さの半分）を入れます。
- `Hand` には `trackLength`（手首→中指の付け根）と `trackRadius`（手のひらの幅の半分）を入れます。指を追跡している時、手のひらは手首→中指の付け根（0→9）に合わせます。
- 指の太さは、追跡した手のひらの幅とモデルの手のひらの比率から決めるため、人の手の大きさに合わせて変わります。

## 寸法と縮尺

- 単位は自由ですが、**部品の長さ（原点から次の関節まで）を `baseLength` として `config.js` に書きます**。`arm-mk1.glb` は上腕・前腕 1.0、手 0.9（手首から中指の先端まで）です。
- 部品の太さ（半径）を `baseRadius` として書きます。`arm-mk1.glb` は上腕 0.17、前腕 0.13、手 0.15（手の幅の半分）、`arm-neon.glb` は 0.14・0.11・0.13、`arm-titan.glb` は 0.19・0.155・0.17 です（細身・重量級の見た目の差が残るよう、モデルごとの値で割っています）。
- プログラムは次のように拡縮します。
  - Y方向：追跡した区間の長さ ÷ `baseLength`
  - X・Z方向：腕の太さ（肩幅 × 0.14 × 太さ設定 × 装備の太さ）× `radiusScale` ÷ `baseRadius`
- `radiusScale` は簡易形状と同じ比率（上腕 1.0、前腕 0.85）にしています。
- **体格に合わせた太さ**：人物の切り抜きマスク（MediaPipe Pose の segmentation mask）から上腕・前腕の実際の幅を5フレームごとに測り、なめらかにして使います。腕を体の横に下ろして片側が胴体とつながる時は、見えている側の2倍を幅とします。測れない間は肩幅から推定します。覆う倍率などは `config.js` の `BODY_FIT` で調整します。

## 左右

3つのモデルはすべて **右腕** として作っています（外側＝+X、体側・親指＝-X、手の甲・前面＝+Z）。
`config.js` の `mirrorLeft: true` により、左腕（MediaPipe の 11-13-15）では部品を X 方向に反転した別 instance として表示します。three.js は反転した物体の面の向きを自動で補正するため、陰影は崩れません。
ただし文字・ロゴなど反転すると読めなくなる模様を入れる場合は、左右別のファイルを用意してください。

## マテリアル（外観の変更）

マテリアル名で役割を区別し、装備の色・素材（#10）から変更します。

| マテリアル名 | 役割 | 変更される値（`DESIGNS`） |
|---|---|---|
| `shell` | 外装 | `metal`（色）、`rough`（粗さ） |
| `joint` | 関節・フレーム | `joint`（色） |
| `emission` | 発光ライン | `neon`（色・発光色）、`glow`（発光の強さ） |

マテリアルは左右の instance ごとに複製するため、片方だけ色を変えることもできます。テクスチャは使っていません。使う場合も外部ファイルを参照せず、GLB内に埋め込んでください。

## 読込の流れ

1. APPLY で `model` を持つ装備を選ぶと読込を始めます（読込中は簡易形状を表示）。
2. 必要なノードを確認し、左右の instance を作って表示を切り替えます。
3. 404・ノード不足・壊れたファイルの場合は、画面に案内を出して簡易形状で表示を続けます。描画は止まりません。
4. 読込中に別の装備やRESETを選んだ場合、古い読込の結果は使いません。
5. 一度読み込んだモデルは、ページを開いている間は再利用します（RESETでは解放しません）。

## 腕のギミック（`gadget-launcher.glb`）

ARMS の `GADGET` で AUTO または種類を選ぶと、前腕に射出装置が付きます（FIST は装置を使わず手そのものが飛びます）。

| 種類 | 動き | 参考にしたゲーム |
|---|---|---|
| PLASMA | 光の弾。溜めるほど大きく遠くへ飛び、命中すると光の輪になって弾ける | ロックマンのチャージショット |
| NET | ネット弾が飛び、命中点で光る網に広がって消える | ― |
| HOOK | 3本爪のフックがケーブルで飛び、爪を開いて巻き取られる | ― |
| FIST | 手と指がケーブルでつながったまま飛び、噴射しながら戻る | ロックマンV のロケットパンチ、Overwatch の Doomfist |

- **AUTO（初期設定）**：手の形と動きでギミックが変わります。画面左下の操作ガイドに一覧を表示し、認識した形が光ります。

| 手の形・動き | ギミック |
|---|---|
| 人差し指だけを上へ立てる | 指先の火 |
| 腕をまっすぐ上げて手を開く → 拳を握る（または腕を下ろす） | PLASMA（開いている間に溜まる） |
| 人差し指と小指を立てる（約0.2秒） | NET（スパイダーマンのウェブ） |
| 人差し指を横・前へ向け、親指を立てる（ピストルの形、約0.2秒） | HOOK |
| 拳を握って肘を勢いよく伸ばす（約0.35秒以内に曲げた状態から伸ばす） | FIST（ロケットパンチ） |

  手の形が見えない（カメラから遠い）時は、腕の動きだけで PLASMA の溜めと FIST のパンチが動きます。判定は `js/gadget-logic.js` の `classifyHand()`・`createGestureTrigger()`・`createPunchDetector()` です。
  似た形を取り違えないよう、指は「伸びている／曲がっている／どちらとも言えない」の3段階で判定し（指先の距離と第2関節の角度）、あいまいな時は何もしません。火とピストルは人差し指の向き（上／横）で分けます。手の形は直近6フレームのうち4フレーム以上同じ時だけ採用します。
- **溜めて撃つ（種類を1つ選んだ時）**：腕をまっすぐ伸ばして肩の高さより上に向けると溜め始め（ふたが開き、砲口に光が溜まる。画面下に CHARGE を表示）、腕を下ろすか、握った拳を開くと発射します。満タンのまま約0.8秒たつと自動で発射します。弾は発射した瞬間の腕の向きへ飛びます（Cyberpunk 2077 の腕の射出システムの「短く押す／溜める」を参考に、溜めが見えるようにしています）。
- `▶ FIRE（テスト）` ボタンと G キーでは、最大の溜めですぐに発射します。
- **指先の火**：人差し指だけを立てると、指先に炎が点きます（手を追跡している時のみ）。

| ノード名 | 原点 | 動き |
|---|---|---|
| `LauncherBase` | 前腕表面への取付面の中心 | 前腕に固定（+Y＝手首方向、+Z＝腕の外側） |
| `LauncherHatch`（`LauncherBase` の子） | ふたの蝶番（肘側の端） | X軸まわりに最大70°開く |
| `LauncherBarrel`（`LauncherBase` の子） | 砲身の後端 | +Y方向へ 0.14 伸びる。砲口は原点から +Y 0.27 |
| `HookHead`（子に `HookProng0`〜`2`） | フックの後端 | 爪は各自のZ軸まわりに40°開く |
| `NetPod` | ネット弾の後端 | 命中点で光る網（コードで生成）に変わる |

- 容量 212,568 bytes。マテリアル名は腕と同じ `shell` / `joint` / `emission` で、選んだ装備の色になります。PLASMA の弾・網・ケーブル・炎はコードで作るため、モデルはありません。
- **光の表現**：発射の閃光・命中の閃光と火花・衝撃波の輪・腕を照らす光・画面の揺れを付けています。プラズマ弾はゆらぐエネルギーの球と電気、NET は波打ちながら広がる光の網、HOOK・FIST はたるむ金属のケーブルです（`js/fx.js`）。指先の火と FIST の噴射は、流体シミュレーションで作った炎の連番画像に火の粉・煙・光を重ねています（`js/flame.js`、`assets/fx/README.md`）。
- 光る物は `js/bloom.js` でにじませます。FPS が低い時は TRACKING SETTINGS の `Effects quality` を LOW にすると、にじみ・煙を止めて軽くなります。
- 取付位置・飛距離・溜め時間などは `config.js` の `GADGET`、火は `FLAME`、各段階の時間は `js/gadget-logic.js` の `shotTiming()` で調整します。

## 素材の出典・利用条件

3つのモデルはいずれも外部の素材・テクスチャを使わず、Blender 5.2 の Python（bpy）スクリプトで形状を組み立てて生成したオリジナルモデルです。スクリプトの作成と生成にはAI（Claude）を使用し、内容は人が確認しています。
Blender で開いて編集できます（`File > Import > glTF 2.0`）。編集後は `File > Export > glTF 2.0`（形式：glTF Binary `.glb`）で書き出し、ノード名・原点・+Y方向・マテリアル名を保ってください。
外部の素材を使う場合は、出典URL・作者・ライセンスをこの表に追記してください。

| ファイル | 作者・出典 | ライセンス・利用条件 |
|---|---|---|
| `arm-mk1.glb` | HAL208 チーム（Blender + AIで生成） | チーム内の作品用。外部素材なし |
| `arm-neon.glb` | 同上 | 同上 |
| `arm-titan.glb` | 同上 | 同上 |
| `gadget-launcher.glb` | 同上 | 同上 |
